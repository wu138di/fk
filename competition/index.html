🛠

怎么做

按照以下步骤完成三个模块的开发

① 环境准备
安装 DevEco Studio（最新版）→ 配置 OpenHarmony SDK 6.0 Beta1 及以上 → 下载组委会下发的参考源码包，在 IDE 中打开基础工程。
② 模块 A — 导入外部 API
打开 oh-package.json5， 添加指定依赖项 → 运行 ohpm install → 在代码中 import 对应接口 → 确认构建通过（Build → Rebuild Project）。
③ 模块 B — 界面设计
在 .ets 文件中编写 @Component → 使用 Column/Row/Text/Button 等组件构建布局 → 为按钮绑定 onClick 事件并验证响应逻辑。
④ 模块 C — 数据解析
接收组委会给定的指定格式数据（JSON / 字符串）→ 用 JSON.parse() 或字符串处理逻辑解析 → 将各字段值绑定到页面 Text 组件显示。
⑤ 录制演示视频
每个模块录制一段独立视频，单段时长 ≤ 2 分钟， 清晰展示功能运行效果。建议使用模拟器录屏，并打开扬声器做语言解说。

容易丢分点

提交前逐项核查，避免低级失误

风险点 危险等级 应对方法
模块 A 构建失败
依赖版本号写错或未执行 ohpm install		 ● 高 提交前 Rebuild Project，确认无 error 日志
模块 B 页面空白
组件未在 @Entry 页面注册，或 build() 结构不完整		 ● 高 在真机 / 模拟器上运行一次，录屏前确认界面可见
模块 C 数据展示为空
数据格式与组委会指定不一致，或解析未覆盖边界		 ● 高 用组委会提供的原始数据完整跑一遍，截图留存
视频超过 2 分钟
超时部分评委可能不予查看		 ● 中 剪辑工具裁切后检查时长，控制在 1:50 以内更稳妥
视频无声音 / 画质模糊
评委无法判断操作步骤意图		 ● 中 录制时开麦或加字幕，分辨率 ≥ 1080p
队伍信息不完整
缺学院名称 / 作品名 / 成员信息		 ● 中 对照提交清单逐项填写，交叉验证
源码依赖本地绝对路径
评委环境中构建直接报错		 ● 低 用相对路径，提交前在全新目录中克隆后构建验证
